4. Why GEMSDOE32's 0.2778 is the leader, and whether it can be beaten

GEMSDOE32's top entry (h33-h33-2-b2-20261004T220000Z-e5eb6e7e-zeros, owner-report 0.2778) is a "dotted" submission: a sparse set of points placed on/near corroborated fault traces, thinned for separation, then binarized to {0,1}. Its apparent edge comes from concentrating prediction mass where faults are already known to exist (high true-positive recovery) while keeping false-positive mass low through tight spacing and thinning.

Can it be beaten? Possibly, but not by copying it (that would be a duplicate and is prohibited) and not without organizer-confirmed ground truth. A defensible improvement would need to (a) recover withheld catalogue segments at a higher holdout-DTI than the incumbent, (b) add genuine off-catalogue discoveries, and (c) pass the registry-duplication gate (≤0.90 rank correlation and ≤70% of dots within 3 px of any registry raster). No such validated candidate exists in this repository yet.

5. How to make a submission (when authorized)

  1. Generate a new single-band GeoTIFF within an assigned method lane, using the shared feature stack, scripts/evaluate_holdout.py and scripts/submission_writer.py (no private forks).
  2. Validate it: CRS EPSG:32611, shape 3730×3292, transform matching the sample, single band float32, all values finite and in [0, 1] across the whole array (this prevents the portal error "Predicted values must be in range [0, 1]"), zero NaNs, and 0 dots on catalogue faults.
  3. Estimate the score only as holdout-DTI (evaluator version, withheld positives, 95% CI). A projection is never written as a score.
  4. Check uniqueness: rank correlation ≤ 0.90 and ≤ 70% of dots within 3 px of every registry raster, before placement and on the final dots.
  5. Get a selector decision: a separate weekly-slot selector must approve the slot within the cap shown on the submission page. Format validity is not submission authorization.
  6. Submit on DrivenData GEMS: choose the file, add the short note (≤140 characters, e.g. "clustering with k=25"), and confirm the live competition and quota.
