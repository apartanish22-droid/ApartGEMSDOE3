Why GEMSDOE32 is a useful lead, not a guarantee

The identifier suggests a sparse/dotted variant of the H19-5/D2.8 family. A plausible explanation is less redundant spatial emission and more useful coverage; the official metric favors reducing missed faults relative to false alarms, while distance weighting softens small positional errors. But the actual raster, code, receipt, evaluator, and holdout are absent here. This is a hypothesis, not a verified causal explanation. We cannot claim to beat its reported value or forecast leaderboard performance.

What is needed before creating a TIFF

  1. Authenticated competition data and the official sample template.
  2. The assigned single-method lane, cached feature stack, shared holdout evaluator/writer, and complete raster registry.
  3. Leakage-safe segment hide-and-recover validation, feature-only canaries, paired confidence interval, and full pre-placement/final-dot uniqueness checks.
  4. Automated file-format validation and separate selector approval under the actual weekly cap.

There is a fail-closed GeoTIFF preflight tool in this repository. It does not generate submissions and does not establish scientific quality or selector approval.
